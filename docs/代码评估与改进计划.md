## 四、亮点（均经实测验证）

1. **精修指标口径确实已修正**（README 的核心宣称成立）
   旧版 `Rexp` 分母配错权重，实测 GOF 曾达 920。本次实测合成数据 **GOF=1.033**、`metrics_valid=True`，`wR/Rp/Rexp/GOF` 同源自洽，单位权时明确标注「不可解读」而非给假数字。这是本轮最有价值的工程改进。
2. **精修物理精度高**：合成 ZnO 晶胞回收误差 **0.095%**，0.64 s 完成，说明「面积归一 + 分阶段释放 + 种子化起点」这组改法有效。
3. **物相检索判别力强**：干净峰表下 ZnO score 0.132 vs 次名 0.786（分离 5.9×）。
4. **国际化是真实交付，不是纸面宣称**：实测三语键集 **各 904 键、双向差集全为 0**；缺键回退链（当前语言 → 中文 → 原键）实现正确，不再漏出裸键名。
5. **运行期工程稳健性超出同类项目平均水准**：`main.py` 覆盖了启动诊断、faulthandler 原生崩溃栈、内核命名互斥量单实例（kill-safe）、5 秒硬退出看门狗（防幽灵进程）、`--safe-render` 保守渲染、`--diagnose` 占用反查、全链路 UTF-8 —— 每处都附**现场实证**注释（如「Win11 24H2 + Iris Xe 驱动，9 次启动 6 次死在 window.show()」）。
6. **分层纪律好**：`services/` 不依赖 Qt，可独立单测；错误处理几乎都带 `# noqa: BLE001` + 理由，属有意识的防御式设计而非疏忽。
7. **文档密度高**：`docs/` 19 篇，含基准报告、分步实施手册、已知问题清单，且**开发者自述的已知问题与实测吻合**（见 §六 对照）。

### 🟠 P1-3 峰检测默认零峰高下限 → 噪声峰淹没 FoM 特异性项

`services/peak_detection.py` 的 `PeakDetectOptions` 默认值：`min_prominence_frac=0.0`、`min_signal_abs=0.0` —— **无任何幅度下限**，仅靠 `sigma_threshold=3.0` 的统计判据。

**实测（ZnO 合成谱，真峰 11 条）**：

| 指标 | 值 |
|---|---|
| 应用主路径 `detect_peaks_from_data` 检出 | **102 峰** |
| 其中匹配真峰位置 | 12 峰，强度中位数 **808** |
| 其中噪声峰 | **90 峰**，强度中位数 **41**（= 真峰的 **5%**，最高仅占谱峰高 1.96%） |
| FoM 特异性项 `unexp_ratio = 90/102` | **0.88** → 惩罚项 **0.265**（权重 0.30 被噪声**打满**） |

**传导效应**：FoM 的特异性项（用于抑制"只解释少数几条峰却排在前列"的伪匹配）**被噪声饱和，完全丧失区分力**。实测同一份数据，ZnO 得分从「干净峰表 0.132」虚高到「自动检峰 0.312」，与第 2 名的分差从 **5.9× 压缩到 2.2×**。

**影响路径确认**：
- `PhaseIdentifier.identify(peaks=None)` → 内部调 `detect_peaks_from_data`（`phase_identifier.py:84-85`）
- MCP `search_phases` 在未预检峰时即走此路径 —— 实测返回 **Zincite score=0.3125**（与虚高值一致）
- 即「加载数据 → 直接检索」这一最常见流程，拿到的都是被噪声压缩后的分数

**⚠️ 但简单加峰高下限是错误修法（已用对照实验证伪）**：把 `min_prominence_frac` 设为 0.02，检出从 68 降到 9 峰，**微量相 Rutile 从第 2 名掉到第 3 名**（真实弱峰被一并删除）。正解见 §六 改进项 P1-3。

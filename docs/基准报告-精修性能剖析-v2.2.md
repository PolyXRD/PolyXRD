# 基准报告 · 精修性能剖析 v2.2（S15）

> 剖析对象：内置引擎 (builtin) 全预算精修 7-1 / 7-2（与 v2.1.0 基准同口径：
> `max_cycles=10, n_starts=1, max_nfev_per_start=80, use_caglioti=True,
> wR_threshold=None`），cProfile + 计数埋点（谱合成 monkeypatch 计时 +
> CIF 峰表缓存命中统计）。探针脚本不入库；本报告为唯一产物。
> 复测 7-1 wR=34.517%（基准 34.52 ✓）、7-2 wR=38.082%（基准 38.08 ✓）——口径一致。

## 一、四问答案（手册 §S15）

### ① 各起点实际 nfev

| 试样 | 起点 | wR | nfev（上限 80） | 耗时 | 备注 |
|---|---|---|---|---|---|
| 7-1 | start 1/1 | 35.799% | 80（打满） | 737.1 s | 两个起点 cost 完全相同 (1.748e+06) |
| 7-1 | start 2/1 | 35.799% | 80（打满） | 842.9 s | **与起点 1 结果逐位相同 → 843 s 纯浪费** |
| 7-2 | start 1/1 | 38.879% | 80（打满） | 3036.0 s | |
| 7-2 | start 2/1 | **343.364%** | 80（打满） | 1726.6 s | 观测峰种子起点彻底失败 (cost 78×)，**1727 s 纯浪费 (33%)** |

- `n_starts=1` 实际仍跑 **2 个起点**（第二个 = W 系列加的"观测峰种子化起点"）。
- 两个试样起点 2 都是**全损**：7-1 收敛到与起点 1 逐位相同（无信息），
  7-2 直接崩到 343%（无价值）。合计浪费 7-1 47% / 7-2 33% 墙钟。

### ② 单次谱合成耗时 × 评估次数

| 试样 | 评估次数 | 合成总耗时 | 单次耗时 | 占墙钟 |
|---|---|---|---|---|
| 7-1（1893 峰, 7251 点） | 6 438 | 1 706.1 s | **0.265 s** | **95.6%** |
| 7-2（5192+ 峰, 7251 点） | 5 513 | 5 223.1 s | **0.947 s** | **98.3%** |

- **评估次数远超 nfev**：`max_nfev_per_start=80` 只数目标函数评估，而
  `least_squares` 的 **2-point 数值雅可比不计入 max_nfev** —— 每迭代额外
  n_params≈22 次评估。实际每起点 ≈ 80 + ~140 迭代 × 22 ≈ **3 200 次合成**
  （7-1: 6 438 / 2 起点 ✓）。"80 nfev 预算"真实含义是 ~40 迭代 × 22 倍放大。
- cProfile 热点（7-1, tottime）：
  `_area_normalized_profile` **1 217 万次调用 / 1 361.8 s (76%)** ——
  窗口化路径对**每个峰逐次调用标量 Python 函数**；
  `searchsorted` 2 434 万次 / 86 s。
  **瓶颈 = Python 层每峰开销，不是 FLOPs** —— 矢量化空间巨大。

### ③ 抛光占比

| 试样 | 抛光评估（自适应预算） | 改进 | 折算耗时 | 备注 |
|---|---|---|---|---|
| 7-1 | 675 次（预算 675 打满） | **wR 35.799% → 35.799%（零改进）** | ≈179 s (10%) | 全部白跑 |
| 7-2 | 390 次（预算 390 打满） | 38.879% → 38.660%（0.22pp） | ≈370 s (7%) | 微弱 |

- 真正有收益的是 **bg-polish（Chebyshev deg=6）**：7-1 35.799→34.517、
  7-2 38.660→38.082，各仅个位数次评估。
- 结论：参数向抛光在两大难试样上**投入产出极差**，需要无改进早退。

### ④ CIF→|F|² 峰表是否重复生成

- **否**。实测：7-1 全程 7 次调用 / 7 次真算（7 相各一次），7-2 为 6/6；
  v0.15.1 缓存（`_cif_peak_cache`，key = CIF 来源+λ+2θ 范围）在
  多起点/抛光/背景抛光全程命中。**此项无优化空间，也排除嫌疑。**

## 三、S16 优化排序（按预期收益）

1. **矢量化窗口化合成**（主杠杆）：`spectrum_from_refs` 窗口路径由
   "逐峰 Python 循环 + 标量 profile 函数"改为"拼接窗口 + 整块矢量求值 +
   `np.add.at` 分段归位"。数学逐点等价，预期合成 5–15×；
   仅此一项 7-1 → ~300 s、7-2 → ~700–900 s 量级。
2. **劣质起点中途剪枝**：起点迭代中途 cost 若 > K× 当前最优（如 5×）即终止
   （7-2 起点 2 cost 78×，前几十次评估即可识别）→ 省下 7-2 的 33%。
3. **抛光无改进早退**：连续 ~150 次评估无改进即停（7-1 的 675 次零改进可省）。
4. ~~CIF 峰表缓存~~：已存在且生效（§一.④），无需动作。
5. ~~cutoff 窗口化核实~~：确认生效（M26 路径未被旁路），但逐峰 Python
   开销使其收益打折 —— 由第 1 项接管。

验收门禁（手册）：每项独立 wR 劣化 ≤0.3pp；目标 7-1 ≤480 s、7-2 ≤900 s。

## 四、S16/S17/S18 落地结果（2026-09-26）

### 4.1 实现（`rietveld_refiner.py`，全部默认关 = 精确档逐位不变）

| 项 | kwargs | 精确档 | 快速档 (`perf_profile="fast"`) |
|---|---|---|---|
| 截断窗宽 | `cutoff_fwhm` | 100（现状） | **25**（合成 ~4×） |
| 灾难起点剪枝 | `start_prune_factor` | 关 | **25**（cost > 25× 最优 → 中途终止） |
| 起点筛选 | 同上联动 | 关 | 3 轮迭代后 cost 未 < 0.98× 最优 → 终止 |
| 抛光无改进早退 | `polish_early_stop` | 关 | **250** 次连续无改进即停 |

- `perf_profile` / 各参数写入 `fit_params`（`perf_profile`/`cutoff_fwhm`/
  `start_prune_factor`/`polish_early_stop`），报告与 UI 可审计（S17）。
- **结论修正**：剖析初判"逐峰 Python 调用开销是瓶颈"**不成立** —— 实测
  112µs/峰 ≈ 2000 点窗口的真实 exp 计算量；矢量化拼接路径反而因
  gather/scatter 变慢（0.54s vs 0.265s/评估，已撤回）。有效杠杆是
  截断窗宽与起点/抛光浪费，见 4.2。

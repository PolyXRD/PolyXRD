## 0. 一页结论

**用户对 `Rexp` 的直觉是对的：它不是"显示不好看"，而是一个真实的算法缺陷。**
实测 2-1 试样的当前 `Rexp` 比标准值小 **130.9 倍**，`GOF` 给出 **961.4**（标准定义下应为 **7.34**）。
此外还定位到另外三个同等级别的引擎缺陷（背景冻结、峰形非面积归一、定量语义错误），
并用**合成数据自检**量化了各自的贡献。

一句话概括诊断:

> **"自动精修效果差"的主因不是优化器能力，而是 ① 正向模型不完备 ② 评价指标与目标函数不一致 ③ 起点差。**

三条改进主线:

| 阶段 | 主题 | 收益量级 | 风险 |
|---|---|---|---|
| **P0** | 把"尺子"修对（指标 + 参数计数 + 有效性标志） | `Rexp`/`GOF` 从无意义 → 有物理意义 | 最低（不动物理模型） |
| **P1** | 让正向模型物理正确（背景入拟合、峰形面积归一、参数化/投影） | wR 从 20~30% → 噪声底附近 | 中 |
| **P2** | 真 Rietveld（结构自由度入向量 + 定量语义修正） | 可信 wt%，与商业引擎可比 | 中高（依赖索引库列迁移） |
| **P3** | 自动精修策略（观测峰种子化 + 先 Le Bail 后 Rietveld + 诚实失败模式） | "一键自动"真正可用 | 中 |

## 1. 背景

上一版方案（`docs/精修算法改进与MAUD引擎接入方案.md`）解决的是**"数据里没有结构"**这一前提问题，
路线 A（内置引擎止血）、B（补齐结构来源）已在 v0.15.2 交付：

- builtin 引擎改为走 CIF 结构 `|F|²` 参考峰（pymatgen 现算）；
- 每相增加各向同性晶胞缩放自由度；对称展开（非对称单元→P1 展开）、March-Dollase 织构修正落地；
- 内置 118 矿物参考库峰表整体重算（库 0.4.0→0.5.1）；
- 实测 2-1 wR 19.43%、4-1 wR 19.69%。

**本轮复评（2026-09-23）发现：wR 上去了，但"评价指标本身"和"正向模型"仍不对。**
即上一轮修的是"有没有结构"，这一轮要修的是"精修这件事在数学上是否自洽"。

## 2. 现状诊断（`rietveld_refiner.py`，含复现证据）

### 2.1 Rexp / GOF 数值错误（P0·最高优先）

`_calc_profile_metrics`（`rietveld_refiner.py:2122`）用的是**标准 Rexp 公式**，但分母配的是**单位权**：

```
Rexp = sqrt((N-P) / Σ w·y²) × 100     ← 公式对
weight=None → w ≡ 1  → 分母变成 Σ y²   ← 但配对错了
```

标准定义里 `w = 1/σ²`；计数统计下 `σ² ≈ y`，所以分母应是 `Σ y` 而非 `Σ y²`，相差一个 `≈ y` 的量级。
真实试样 2-1 实测:

| 量 | 当前代码 | 标准定义（Poisson 权） |
|---|---|---|
| Rwp | 20.54 % | 20.54 %（Rwp 与权重尺度无关，本身没错） |
| **Rexp** | **0.0214 %** | **2.797 %** |
| **GOF** | **961.4** | **7.34** |

⚠️ 误差因子**随数据强度标尺漂移**（不是常数偏移）→ 当前的 `Rexp/GOF` **没有物理意义**。

连带缺陷:

- `stat_weights="poisson"` 那条路径也错了：代码把权重归一到均值 1（`rietveld_refiner.py:1072`），
  而归一化会乘掉统计尺度 → 实测 `Rexp` 仍偏小 18 倍（Rwp 32.14% / Rexp 0.156% / GOF 205.8）。
- `Rb` 实际算的是 `Σ|Δy|/Σy`，那是 **Rp（轮廓 R）不是 R_Bragg**（真 Bragg R 需要每个 hkl 的积分强度）。
- GSAS-II 路径传 `n_params=0`（`rietveld_refiner.py:377`），Le Bail 用 `n_params=1` → 这两条路径的 `Rexp` 同样失真。

### 2.2 背景"一次性冻结"，且勾选框是空转

`bg = self._estimate_background(...)`（`rietveld_refiner.py:1044`）用 median 滤波估一次就固定；
`param_mask["background"]` 在 builtin 内是 **no-op**（代码注释自认）。

**合成自检**（用引擎自己的正向模型生成数据 + Poisson 噪声；真值 50/50、已知平滑背景、噪声底 1.087%）:

| 配置 | Rwp | 回收的 η | 回收的 wt% |
|---|---|---|---|
| A 现状（median 背景一次性冻结） | **5.041 %** | **0.953**（真值 0.6） | 49.2 / 50.8 |
| B 背景给精确值 | **1.012 %** | **0.599** ✓ | 49.87 / 50.13 |

**结论：即使正向模型与数据完全自洽，仅"背景估计"一项就把残差抬到噪声底的 4.6 倍**，
并把峰形参数 η 污染成 0.953（背景误差与峰形参数耦合、互相补偿）。这是真实试样"Rwp 地板"的第一根因。

### 2.3 峰形是"峰高归一"而不是"面积归一"

`phase_display.spectrum_from_refs` 里 `gauss` / `lorentz` 都是**中心值为 1** 的形式（`phase_display.py:255-259`）：

- 模型**积分强度 ∝ FWHM**（实测 面积/FWHM = 131.5 恒定）；Rietveld 要求积分强度 = m·LP·|F|²·S，**与峰宽无关**；
- η 从 0→1 会让面积变化 47% → **η 不是混合比**；
- 固定 FWHM 时该错误被 scale 整体吸收（所以平时看不出来），**一旦 Caglioti 开启（默认精细模式就是开的）就暴露**。

15–120° 对照实验（真值用面积归一 + Caglioti U=0.012/V=−0.004/W=0.004，噪声底 0.359%）:

| 模型 | Rwp | 回收的 U | 回收的 η | wt% |
|---|---|---|---|---|
| 现状（峰高归一） | **5.996 %** | **−0.0021**（真值 0.012） | 0.587 | 49.2 / 50.8 |
| 改为面积归一 | **0.340 %** | **0.0114** ✓ | 0.600 ✓ | 50.02 / 49.98 |

⚠️ 不只是 Rwp 差 5.6 个百分点：**Caglioti 参数被拟合到完全错误的数值**
→ 由峰宽导出的**晶粒尺寸/微观应变信息目前不可信**。

### 2.4 定量 wt% 不是质量分数

`weight_pcts = opt_weights/Σw`（`rietveld_refiner.py:1536`）只是相对强度权重归一，
缺 Rietveld 的 `S_p·(ZMV)_p` 关系，也没有 μ 差异的 Brindley 校正:

- 真实 2-1：短预算跑出 65.7/34.3（真值 50/50）；完整基线 60.66/39.34；
- 4-1 更严重：真值 19.9/21.3/22.5/36.3 → 实测 32.7/**1.1**/**3.1**/63.2。

→ 与界面上"质量分数 (%)"的措辞不匹配。

### 2.5 它确实不是 Rietveld（结构性原因）+ 次要缺陷清单

当前 fit 向量 = `weights(n) + fwhm + eta + scale + zero + U + V + W (+每相 1 个各向同性晶胞缩放) (+织构 r)`。
**没有**：原子坐标、占位、U_iso/B_iso、全晶胞参数（只有一个全向缩放 ±2%，各向异性失配修不了）、
样品位移（`Δ2θ = −2s·cosθ/R`）、低角不对称、Kα2。

次要但真实的点:

| 项 | 现状 | 后果 |
|---|---|---|
| Kα2 | 未处理。2-1 的 36.22° 主峰右侧有肩（36.24/36.26 台阶），Kα2 应落在 36.313°（Δ=0.093°，与 FWHM 同量级） | 峰位/峰形残差被系统性抬高；菜单里有剥离工具但精修模型不知道、也不强制 |
| 规范退化 | `y = scale·Σ w_p S_p` 中 `(scale·c, w/c)` 等价 → Jacobian 天然秩亏 | 只靠 `w≤30`、`scale≤10000` 勉强兜住 |
| 优化器 | `least_squares(trf)` 未传 `x_scale`（`rietveld_refiner.py:1387`）；"冻结"用 `lb=ub=init±1e-7` 近似；无 esd/协方差；"抛光"是对手工网格做坐标式扫描 | 参数跨 5 个数量级，收敛质量与速度都受影响 |
| 质量分级两套 | `_refine_builtin` 用 `<5/<10/<20`（`:1585`）；`RefinementResult.quality_grade` 用 `<2/<5/<10/<20`（`models/refinement.py:58`） | 同一结果对象给出两种等级 |
| 收敛语义 | `converged` 取的是多起点里某个 `res.success`，不是抛光后最终解；`num_cycles` 实际是 nfev | 结果字段语义与名字不符 |

## 3. 四阶段方案

### P0 · 先把"尺子"修对（预估 1–2 天 · 不动物理模型 · 风险最低、收益最直接）

1. **重写 `_calc_profile_metrics`**：权重一律取统计权 `w = 1/σ²`（Poirier：`σ² = max(y,1) + bg`），**不归一化**；
   输出 `Rwp / Rexp / Rp / χ² / χ²_red / GOF`；`n_params` 必须真实（GSAS-II、Le Bail 路径单独口径）。
2. **增加"指标有效性"标志**：只有在"原始计数 + 统计权重"时 `Rexp/GOF` 才可比；否则 UI 显示**"不可解读"**
   而不是给一个漂亮数字。⚠️ `Rexp` 本身 `∝ 1/√Σy`，数据标尺一改就变 —— 必须在产品层写清楚。
3. **`Rb` 改名 `Rp`**；真 Bragg R 另行实现或暂不显示。
4. **合成自检测试（新文件）**：`y_true + Poisson` → 断言 `Rexp` 等于解析值；断言"模型=真模型"时 `GOF ∈ [0.8, 1.3]`；
   断言 `Rexp` 随计数标尺按 −1/2 幂缩放。**这类测试目前完全没有，所以指标错了 130 倍都没人发现。**
5. **外部对账基准**：用已集成的 **FullProf / GSAS-II** 对同一 13 试样各跑一遍，
   把 `Rwp/Rexp/χ²/wt%` 落成 JSON 基线，作为 builtin 的"真值标尺"。
   → **这是唯一能证明指标正确的办法**；是否执行需用户决策（见 §5）。
6. **两套质量分级合并到一处**，且只对 valid 指标生效。

**顺手修的小 bug**（同属 P0 范围）:

- `_refine_gsas2` 的 `n_params=0`；Le Bail 的 `n_params=1`；
- `converged` 不是最终解的状态；`num_cycles` 语义混淆；
- 引擎静默回退虽有 `engine_fallback_reason` 字段，但需确认 UI 真的把它摆到用户眼前；
- README 徽章 1010 项 vs 实际 1016；`pyproject` 1.1.1 vs Release v1.0.1 口径未收口；
- `cod_searcher.py:433` 用 `pickle.load` 读缓存（缓存投毒面，建议改 JSON，那里本来就是 `to_dict()`）。

**验收**: 合成数据自检全绿；2-1 的 `Rexp` 落在 2.8% 量级、`GOF` 落在 7 量级；`GOF` 在"模型=真模型"时 ∈ [0.8, 1.3]。

---

### P1 · 让正向模型物理正确（预估 3–5 天 · 预计 wR 从 20~30% 量级降到噪声底附近）

1. **峰形改面积归一 PV**（统一度/弧度单位）→ 直接吃 §2.3 的收益（合成自检 5.996% → 0.340%）。
2. **背景进拟合向量**：Chebyshev 6 阶（SNIP 只做初值），默认开启、与结构联合精修
   → §2.2 的 5.041% → 1.012% 差距主要靠这一项拿回。
3. **参数化与优化器**:
   - 权重内部约束 `Σw = 1`（消掉规范化退化）；
   - 传 `x_scale` / 对数参数化；
   - **变量投影**：给定 (FWHM, η, U/V/W, zero, cell, texture, bg) 后，模型对**各相 scale 是线性的**
     → 内部解析求解，只对非线性参数做 `least_squares`。
     这一步同时解决收敛质量与"大峰表 10 min/起点"的速度问题。
4. **峰位物理**：零位 + **样品位移** + 低角不对称；**全晶胞参数**（按晶系约束 1–6 自由度）替代单一各向同性缩放。
5. **Kα2**：要么精修前强制剥离并记录，要么模型里加 Kα2 分量（λ2 + 0.5 强度比 + 解析 Δ2θ）。
   **建议后者**（不丢计数统计与低角信息）。
6. **输出参数 esd**（`least_squares` 的 jac 直接可算）+ **分区间/分相残差诊断**
   （低角/高角/各相峰值窗 + 残差自相关 DW 统计量）。
   自动精修最难的部分是"知道模型缺了什么"，这比一个总 Rwp 有用得多。

**验收**: 合成自检 Rwp 达到噪声底量级；2-1/4-1 的检查点 wR 与 v0.15.2 基线（19.43% / 19.69%）相比不劣化，
且 `U/V/W` 回收值落在真值附近（当前是 −0.0021 vs 真值 0.012，完全错误）。

---

### P2 · 真 Rietveld（预估 1–2 周 · 可出可信 wt%）

1. **结构自由度入向量**：坐标 / 占位 / `U_iso`（`B = 8π²U`），按空间群用非对称单元参数化；
   前提是补上 `_extract_atomic_sites` 丢掉的 `U_iso`（**需要索引库列迁移**）。
2. **定量**：`W_p ∝ S_p·(ZMV)_p`；有结构走 Rietveld 标度，无结构**明确定级为 RIR 半定量**
   （`services/rir.py` 已有）并给出不确定度。
3. **织构轴向也进参数**（或球谐）；用 TCH 把晶粒尺寸/微观应变从 FWHM 参数化出来（`crystallite.py` 已有）。
4. **产品分层对齐现实**:
   - "内置引擎 = 免结构全谱拟合（Le Bail 级，快）"；
   - "真 Rietveld（结构自由度 + wt%）需 GSAS-II / FullProf / MAUD"。
   → 现在 README 直接叫 Rietveld 是**过度承诺**；记忆文档里其实已经想清楚了这套分档。

**验收**: 2-1 定量回到 50±5%；4-1 四相各在真值 ±8% 内；`GOF`/`χ²_red` 可解释。

---

### P3 · 自动精修策略（让"自动"真的能收敛到好解）

1. **用观测峰种子化起点**：项目已有一流的逐峰拟合（`peak_fitting.py`）——把它接上来:
   逐峰 FWHM/η → 最小二乘反解 U/V/W 初值；主峰位置 → 零位/位移初值；
   峰强比 → 相分数初值；SNIP → 背景初值。
   → 这是"自动精修难"最直接的解药，而不是继续加多起点数量。
2. **先 Le Bail 再 Rietveld**：Le Bail 不需要结构（人人可用），先稳定 cell + 轮廓 + 背景，再切结构精修。
   这是 GSAS/FullProf 的标准流程，也顺带解决"只装了无机物库（无 CIF）"的产品分档问题。
3. **分阶段释放**：bg/scale → 轮廓 → 零位+位移 → 晶胞 → 结构，每阶段收敛后再放开。
4. **诚实失败模式**：当最终 GOF 偏高且残差有系统结构时，输出诊断清单
   （"未建模 Kα2 / 缺织构 / 疑似未识别相 / 峰宽模型不足 / 背景欠拟合"），而不是给一个好看的 Rwp。

**验收**: 13 试样全部收敛且无人工干预；失败样本给出可读诊断；单试样耗时较现状下降。

## 4. 关于"自动精修本来就很难"的判断

**不完全同意，需要拆开看。** 合成自检说明：**当正向模型正确时，现有"多起点 + 抛光"能把 Rwp 压到噪声底**
（1.012% vs 噪声底 1.087%），参数（η=0.599、FWHM=0.1300、50/50）全部正确回收。

所以"自动精修效果差"的主因不是优化器能力，而是三件事:

1. **模型不完备**（背景冻结、峰形不归一、无位移/不对称/Kα2/结构）→ 残差里是模型误差而不是噪声；
2. **评价指标与目标函数不一致**（单位权 → 目标函数只在意强峰，wR 却按全谱算）→ 优化器在解一个跟"好结果"无关的问题；
3. **起点差**（本可用观测峰反推，却用了几个手写网格点）。

**修完 P0+P1 后，"自动精修"的现实目标应是"稳定收敛到噪声底附近的诚实解，并诚实报告它还差什么"**，
而不是追求 `Rwp < 5%` —— 后者对多相实验室数据本来就不是合理 KPI
（实验室 XRD 的 wR 10–15% 就可发表，这一点项目文档里已有共识）。

## 7. 附录 A｜物相分析与谱峰处理现状（本次实测）

> 本节回答用户的问题："物相分析这一块是可以使用的吧，谱峰处理也 ok 吧"。
> 方法：用 `E:\TEMP\test_xrd\txt\` 的 13 个真实试样，走 App 的真实调用路径
> （`default_peak_list` + `identify_with_element_filter` / `identify_with_cod_inorganics`），
> **只读**，不改任何代码。复现见附录 B。

### A.1 物相识别的候选质量：**可用**（内置库 Top-10 召回 19/20 = 95%）

App 默认数据库源 = `builtin`（`phase_view._db_source_keys[0]`），即 106 相内置矿物库。
用"真值物相在候选里的排名"衡量:

| 试样 | 真值物相 | 候选排名（Top-10 内置库） |
|---|---|---|
| 1-1 | LiFePO4 | #1 |
| 2-1 | ZnO / CaCO3 | #1 / #2 |
| 2-2 | TiO2-anatase / rutile | #1 / #2 |
| 3-1 | ZnO / CaF2 / Al2O3 | #1 / #2 / #3 |
| 3-2 | ZnO / CaF2 / Al2O3 | #1 / #2 / #3 |
| 4-1 | CaF2 / ZnO / Mg(OH)2 / Al2O3 | #1 / #2 / #3 / #4 |
| 5-1 | MgCO3 / CaCO3 / dolomite / quartz / cristobalite | #1 / #2 / #3 / #5 / **漏检** |

**结论：检索与匹配（候选生成）是可用甚至优秀的**——单相与常见多相试样的真值物相基本都在 Top-3 内。
弱项集中在复杂岩石类试样（石英/方石英这类弱峰、重叠峰多的相）与候选池之外的矿物。

### A.2 自动多相组合：**不可全信**（这才是"物相分析不够好"的真实瓶颈）

`PhaseIdentifier.build_refinement_combination`（B&B）在真值相数已知的条件下，
9 个可判定样本里只有 2 个组合与真值一致。典型反例（真值就在 Top-3，却没被选中）:

| 试样 | 自动组合结果 | 真值 | 真值候选排名 |
|---|---|---|---|
| 2-1 | Fluorapatite + Feldspar | ZnO + CaCO3 | #1 / #2 |
| 3-1 | Zincite + Hornblende + Clinochlore | ZnO + Al2O3 + CaF2 | #1–#3 |
| 4-1 | Fluorite + Brucite + Clinochlore + Kaolinite | ZnO + Al2O3 + CaF2 + Mg(OH)2 | #1–#4 |
| 5-1 | Magnesite + Calcite + Dolomite + Muscovite + Clinochlore | + quartz + cristobalite | quartz #5 |

COD 主库路径（`identify_with_cod_inorganics`，检索耗时 2.3–3.9 s）问题更明显:

- 候选**内容**是对的（`O Zn` = ZnO、`Ca F2` = Fluorite、`H2 Mg O2` = Brucite 等都在 Top-5），但**命名是化学式**；
- 组合出现**同相重复**（5-1 的组合里 4 条全是方解石的不同 COD 条目）；
- 也会给出明显不合理的组合（2-1 → `Al8 Ca4 Li4 N12` + 橄榄石类）。

**结论：候选列表可用（人工勾选即可，这也是 App 的主流程），但"一键自动组合"目前会挑出重复相/错误相，"自动混合分析"（top-5 + NNLS）同样只应作为参考。**
→ 列为**另一条改进线**（组合打分需加"同一相去重/化学式去重 + 覆盖残差峰 + 主峰强度一致性"约束），
与本四阶段方案解耦，建议单独排期。

### A.3 谱峰处理（寻峰）：**功能 OK、精度设计合理，但有 30–40 s 的等待尖峰**

- 默认走高精度 `peak_detection`（亚步长峰位精修 + 自适应背景 + 局部 σ 阈值），
  13 试样检出 **44–92 个峰**，峰位/峰形/面积齐备。
- **耗时数据依赖、可复现**（同一试样连测两次几乎相同）:

| 试样 | 峰数 | 寻峰耗时 |
|---|---|---|
| 4-1 | 80 | 0.78 s / 0.78 s |
| 2-1 | 44 | 13.37 s / 13.26 s |
| 7-2 | 92 | 32.67 s / 32.65 s |
| 3-2 | 87 | 40.58 s / 40.51 s |

- **根因已定位**: 默认 `PeakDetectOptions.refine_by_fit=True`（逐峰局部联合拟合，curve_fit）。
  关掉后 **2-1: 13.81 s → 0.01 s、3-2: 42.05 s → 0.01 s，而峰数完全相同（44/44、87/87）**
  → 约 1000× 的开销**只花在"给每个峰精修 FWHM/面积"上**，检测本身是毫秒级。
- **结论**: 谱峰处理本身可用、无正确性问题；
  改进方向是**"快检（parabola）+ 按需逐峰拟合"**（例如只对前 N 个主峰/被选中的峰做局部拟合，
  或把 `refine_by_fit` 变成可选项并在 UI 给出耗时提示），属**低风险性能优化**，同样不在本四阶段方案内。

### A.4 一句话总答

> **物相分析：可用**——候选检索/匹配质量好（Top-10 召回 95%），人工确认后即可进精修；
> 但"自动组合/自动混合"不可全信，复杂样会漏相。
> **谱峰处理：可用**——算法与精度没发现问题；唯一明显短板是个别试样寻峰要等 30–40 s（根因是默认逐峰拟合）。
> 改进确实集中在**结构精修**这一块，本次复核也再次确认：精修侧的缺陷才是"结果不理想"的主因。

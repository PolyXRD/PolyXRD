## 1. 本次复核的三个关键结论（决定优先级）

### 1.1 排序（FoM）已不是瓶颈，**组合选择**才是

实测（本机，`top_n=12`，`expected_count` 取真值相数）：

| 试样 | 真值 | FoM 前几名 | `build_refinement_combination` 结果 |
|---|---|---|---|
| 2-1 | ZnO + CaCO3 | **Zincite 0.159、Calcite 0.519**（第 3 名 0.918） | **Fluorapatite + Feldspar** ❌ |
| 4-1 | ZnO/Al2O3/CaF2/Mg(OH)2 | Fluorite 0.303、**Zincite 0.465**、Brucite 0.547、**Corundum 0.710** | Fluorite/Brucite/**Clinochlore/Kaolinite** ❌ |
| 5-1 | 石英/方石英/方解石/菱镁矿/白云石 | Magnesite 0.594、α-石英 0.601、Calcite 0.686、Dolomite 0.718 | 前四对，**Feldspar 顶替方石英** ❌ |

→ **只改 FoM，用户看到的最终组合不会变**。组合选择必须前置。

### 1.2 根因：B&B 的目标是"覆盖到的实测峰**个数**"，不看强度也不看命中质量

- `_phase_hit_mask`（`phase_identifier.py:349`）：参考峰落在容差内即置位，**布尔、无强度、无质量**；
- `_branch_and_bound_select`（`:363`）：目标 `max |∪ masks_i|`，**FoM 只作平局打破**（`:398-404`）；
- 后果：参考峰表密集的相（氟磷灰石 86 条、长石 312 条、方石英 71 条）靠"数量"覆盖更多实测峰，
  把 FoM 明显更好的真相挤掉；观测峰里还混有噪声峰（寻峰 `min_signal_abs=0`），更利于密集相。

### 1.3 FoM 方案里"参考峰按扫描范围截断收益最大"这一判断**被实测削弱**

5-1 观测范围 20.87–105.12°，方石英 71 条参考峰中 **70 条本就在范围内**：

| 口径 | 参考峰数 | FoM |
|---|---|---|
| 全表（现状） | 71 | 1.051 |
| 仅范围内（原方案阶段 1 第 1 项） | 70 | **1.051（无改善）** |
| 范围内且 I/Imax ≥ 1% | 25 | 1.015（仍差于同试样其他相 0.64–0.76） |

→ 真正的杠杆是**强度可观测性**（哪些参考峰在该样品里"应当可见"），而非几何范围裁剪。
建议与 Match! 的 **I scale factor** 耦合实现（见 S09/S10）。

## 3. M-A · 组合选择修正

### S01 建"组合准确率"基准（先立标尺）

- **目标**：把"自动组合是否选中真相"变成可量化指标。
- **文件**：新增 `scripts/bench_combination.py`；产物 `docs/基准报告-物相组合-v1.md`。
- **做法**：
  1. 试样集：真值相名明确的样本（1-1、1-2、2-1、3-1、4-1、5-1、7-1；5-2/5-3/7-2 亦可用）；
  2. 每试样：`default_peak_list` → `identify_with_element_filter(top_n=12, tolerance=0.2)`
     → `build_refinement_combination(expected_count=真值相数, min_coverage=0.3, peaks=gpl)`；
  3. 指标：**完全命中率**（组合 ⊇ 真值）、缺失相数、多余相数，**并单独记录真值相在
     `identify` 结果里的排名** —— 用于区分"检索没给到"与"组合丢掉了"。
- **边界**：只读；不改任何算法；真值相名 ↔ 库相名的映射表写在脚本里
  （如真值 `LiFePO4` ↔ 库名 `Lithium iron phosphate`，**此映射坑此前导致误判 0.00%**）。
- **验证**：能跑完 13 试样并落 Markdown；**必须复现 §1.1 的三个反例**（2-1/4-1/5-1 组合错误）。
- **回滚**：删脚本与报告（不涉及源码）。

### S02 覆盖向量：由"布尔命中"改为"强度 × 命中质量"

- **目标**：让密集弱峰相不再靠数量取胜。
- **文件**：`src/polyxrd/services/phase_identifier.py`。
- **精确改动**：
  1. 新增 `_phase_cover_vector(phase, obs_tt, obs_int, tol) -> np.ndarray`：对每个实测峰 j，
     取该相所有参考峰里最佳命中的贡献 `cover_j = max_k[(1 - |Δ_jk|/tol)] · w_j`，
     其中 `w_j = obs_int[j]/max(obs_int)`（缺强度时全 1）；无命中则 0。
  2. `_branch_and_bound_select` 增加参数 `cover_vectors`；目标由 `cov = |∪ masks_i|`
     改为 `cov = Σ_j max_{i∈S} cover_i[j]`（按位取最大后求和）。
  3. **保留** `_phase_hit_mask` 供 `_dedupe_results` 使用（勿删，避免连带回归）。
- **边界**：`obs_int` 全 0/缺失 → 退化为等权且质量项取 1（接近旧行为，保证不崩）；
  n>14 的贪心分支也必须改用 cover 向量，**两条路径口径不允许不一致**。
- **验证**：S01 复跑 → 2-1 组合含 Zincite+Calcite；4-1 含 Zincite 与 Corundum；
  完全命中率不低于基线；`pytest tests/test_phase_combination_strategy.py tests/test_multiphase_m11.py -q`，
  若断言依赖旧口径，按新口径更新并注明理由。
- **回滚**：还原这两个函数与调用点。

### S03 目标函数引入"候选质量项"

- **目标**：覆盖数接近时优先选 FoM 更好的相。
- **文件**：同上 `_branch_and_bound_select`。
- **精确改动**：目标改为 `obj(S) = Σ_j cover_S[j] − λ·Σ_{i∈S} FoM_i`；
  `λ` 默认 `0.05 × 平均 cover 权重`，作为模块级常量 `_COMBO_FOM_WEIGHT` 暴露（便于 S14 标定）。
  **保留覆盖优先**：仅当两组合覆盖差 <5% 时质量项才可能翻盘。
- **边界**：`scores` 缺失 → λ 置 0，退回纯覆盖。
- **验证**：S01 指标不劣化；抽 2 个试样打印入选组合的 (cover, ΣFoM) 人工核对。
- **回滚**：λ 置 0 即等价旧行为。

### S04 B&B 池裁剪（防排名外密集相挤入）

- **目标**：杜绝"排名第 9+ 的密集相"靠覆盖数击败排名第 1 的真相。
- **文件**：`build_refinement_combination`（`:482`）池构造处。
- **精确改动**：池构造前按 FoM 升序截断至 `pool_top_n`：
  `expected_count` 有效时取 `max(8, 2×expected_count)`，否则 12；新增 kwargs `pool_top_n=None` 可覆盖。
  截断后仍走原有 coverage/纯金属/掩码过滤。
- **边界**：只影响"进入 B&B 的候选"，**不影响返回 UI 的完整候选列表**；被截断者记入日志（S06）。
- **验证**：S01 完全命中率提升；检查 5-1（若方石英排名 >10，需确认是"检索未给到"而非"被裁掉"，
  用 S01 记录的真值排名对照）。
- **回滚**：`pool_top_n` 传大值（如 100）即等价关闭。

### S05 去重增强（跨公式同结构 + COD 同相多条目）

- **现状**：`_dedupe_results`（`:299`）按 `(formula, elements)` 分组 + 结构同判 + 数据感知多型规则，
  逻辑合理；**但同结构若 formula 写法不同（水合物/空格/大小写）会漏判**。
- **精确改动**：分组键由 `(formula, elements)` 改为 `(normalized_formula, element_set)`；
  `normalized_formula` **复用** `utils/formula_parser` 既有归一化（不要另写一套）；
  结构同判仍用 `_phases_structurally_same`。
- **边界**：归一化只用于分组，**不改写 `phase.formula`**（避免影响展示与导出）。
- **验证**：构造两条 formula 写法不同但结构相同的候选，断言只留 FoM 最优一条；
  5-1 组合里不再出现"同相多条目"。
- **回滚**：还原分组键。

### S06 组合决策可解释性

- **目标**：组合错时能立刻知道"为什么"。
- **文件**：`build_refinement_combination` + 调用方日志通路。
- **精确改动**：仅在传 `log_cb` 时打印（**不改返回值**）：
  `[combo] pool=N(top_n=X) 结果=[相位(cover贡献, FoM)…] 覆盖=Y/Z`，
  以及 `[combo] 被池裁剪丢弃: [相名(rank)…]`。
- **边界**：只打印，不参与打分；不引入 i18n（服务层符号化）。
- **验证**：跑 2-1，日志能看出"Fluorapatite 的 cover 贡献 vs Zincite 的"。
- **回滚**：删打印。

### S07 组合回归测试与口径更新

- **文件**：`tests/test_phase_combination_strategy.py` + 新增 `tests/test_combination_truth_hit.py`。
- **精确改动**：新断言 —— 2-1/4-1/5-1 的 `build_refinement_combination` 结果**必须包含真值相**
  （用 S01 的映射表）。原有用例若断言旧行为（密集相胜出），按新口径更新并注明理由。
- **验证**：`pytest tests/test_phase_combination_strategy.py tests/test_combination_truth_hit.py -q`。
- **回滚**：新测试可先 skip，但不得删除。

### S09 参考峰可观测性（与 S10 耦合，替代纯范围截断）

- **文件**：`src/polyxrd/services/foam.py::compute_fom`。
- **精确改动**：新增参数 `obs_range=None, min_visible_frac=0.0, scale=None`：
  1. 仅 `2θ ∈ obs_range` 的参考峰进 `Σw` 分母（范围外**既不计漏检也不计权重**）；
  2. 若给了 `scale`（S10 的 `s*`）：预期强度 `I_exp = s*·I_ref`，
     `I_exp < max(obs_int)×1%` 的参考峰**不计漏检**；
  3. `scale` 缺失 → 退回 `I_ref/Imax ≥ min_visible_frac`（默认 0.05）的保守口径。
- **边界**：默认参数（`obs_range=None, scale=None, min_visible_frac=0.0`）下行为与现状一致 →
  不影响既有测试；`min_coverage` 与 `Σw` 归一方式不变。
- **验证**：用 5-1 方石英复算，报告给出"范围截断 / 1% / 5% / 尺度驱动"四种口径的 FoM 与排名对照
  （本次已测得前两种：1.051 / 1.015）。
- **回滚**：恢复默认参数即旧行为。

### S10 强度尺度因子（Match! 的 I scale factor）

- **文件**：`foam.py`（计算）+ 候选列表（展示）。
- **精确改动**：在互斥匹配对上求 `s* = Σ(w·I_obs·I_ref)/Σ(w·I_ref²)`；`s*` 记入 `FoMResult`；
  候选列表新增 **"I scale"** 列；`s*` 过小 → 按连续函数降权（惩罚"只配上噪声"的伪匹配）。
- **边界**：`s*` 计算失败 → 该项权重置 0；**`s*` 不参与 `bad` 分母**（不改变归一化）。
- **验证**：构造"密集弱线伪匹配"用例，断言其 `s*` 明显偏小且排名下降。
- **回滚**：关闭该惩罚项。

### S11 位置偏差改陡降核

- **文件**：`foam.py::compute_fom` 的 `sum_dev` 项。
- **精确改动**：`Σ w·(|Δ|/tol)` → `Σ w·(1 − exp(−0.5·(2Δ/tol)²))`（零偏差→0，边缘→≈1）。
- **验证**：合成用例（零偏差 vs 边缘偏差）得分区分度提升 ≥2×；既有测试口径同步更新并注明理由。
- **回滚**：恢复线性核。

### S12 完整性项拆分强弱漏检

- **精确改动**：漏检参考峰中 `I/Imax ≥ 0.5` 的强线权重 ×2，弱线维持现状；
  **与 S09 叠加时顺序必须是"先按可观测性过滤、再拆强/弱档"**。
- **验证**：强线被漏的伪匹配排名明显下降；S08 指标不劣化。
- **回滚**：恢复单一权重。

### S13 标记峰搜索（UI 通路）

- **精确改动**：`search_match` 增加 `marked_peaks`；候选列表加"仅对标记峰再匹配"入口。

## 5. M-C · 复杂多相精修性能（7-2 88 分钟，最刺眼的一条）

> 背景：v2.1-A 的"抛光预算自适应"只覆盖抛光阶段，**我原定验收线（7-1 ≤15 min）未达成**：
> v2.1.0 基准里 7-1 = 1652 s、**7-2 = 5293 s**。

### S15 先剖析，不猜

- **文件**：临时剖析脚本（`tests/probe_*` 风格，不入库）；产物 `docs/基准报告-精修性能剖析-v2.2.md`。
- **做法**：对 7-1 / 7-2 单次精修做 cProfile + 计数埋点，报告必须回答：
  ① 各起点实际跑了多少 nfev；② 单次谱合成耗时 × 评估次数 = 多少；③ 抛光占比；
  ④ CIF→|F|² 峰表生成是一次性还是每次评估重复生成。
- **边界**：只读分析。

### S16 按剖析结论优化（每项独立验收）

候选（按 S15 结果择用；**每项都必须 wR 劣化 ≤0.3pp**）：
1. **多起点提前剪枝**：某起点中途 wR 已明显差于当前最优 → 提前终止；
2. **nfev 上限按峰数自适应**；
3. **相位峰表缓存**：快检/精细/抛光三处若重复生成 CIF 峰表 → 命中缓存；
4. **核实 `cutoff_fwhm` 窗口化在精修路径上确实生效**（M26 做过，需确认未被旁路）。

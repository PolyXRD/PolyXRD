# PDF2-2004 数据库对接说明

> 版本: v0.9.11 · 更新: 2026-09-10
> 目的: 用 ICDD PDF-2 (2004 版) 商用库交叉验证 COD 开源库的识别结果

---

## 一、这是什么

PolyXRD 原先只接 COD 无机物库 (71,199 相)。本模块把 **ICDD PDF-2 2004**
原始数据解析成与 COD **接口完全一致**的 SQLite 索引，作为第二条物相识别路径，
用于对照"开源库 vs 商用库"的结果差异。

| 项目 | COD 无机物库 | PDF2-2004 库 |
|---|---|---|
| 物相数 | 71,199 | **163,834** |
| 覆盖 | 仅无机物 | 无机 + 有机 (PDF-2 全集, 含 Deleted 卡片) |
| SQLite 体积 | ~258 MB | **~205 MB** |
| n_peaks 均值 | 266.5 (全反射列表) | 63.8 (实测卡片峰) |
| 空间群 | CIF 里有 | **119,197 (72.8%)** |
| 晶胞参数 | CIF 里有 | **133,935 (81.8%)** |
| 索引文件 | `cod_data/COD_inorganics.sqlite` | `cod_data/PDF2_2004.sqlite` |
| 原始数据 | — | `E:/TEMP/XRD-PDF2-2004/pdf2 - 2004.dat` (587 MB) |

两个库都**不进 git**（`.gitignore` 的 `cod_data/*.sqlite*` 覆盖），
PDF2 索引需要本地重建，见第三节。

## 〇、两个曾踩过的坑

### 0.1 初版解析器丢失约 85% 卡片（已修）

初版正则硬编码了记录标记的两个字母：

```python
_RE_RECORD_ID = re.compile(r"P(\d{6})X([A-Z0-9+*])")   # ❌ 只认 P...X...
```

真实 PDF-2 是**无换行的 80 字符定宽流**，标记 token 恒在 field 第 71 列起：

```
<数据集字母 P/D/...><6位卡片号><序列字母 X/R/H/...><类型 1/3/7/I/K>
```

两个字母都会变：石英 470715 全用 `P...X...`，方解石 010837 全用 `D...R...`，
211487 用 `P...H...`。32 MB 样本实测序列字母 X 仅占 35%。

后果：只入库 25,237 相（真实 ~164k），**方解石 010837 完全缺失**，
且跨卡片串数据。修法（见 `parse_pdf2_record` 上方注释）：

1. 正则锚定第 71 列 + 接受任意序列字母 → 25,237 → **163,834**
2. 数据区收窄到前 67 列（67~70 列是标志区，混入 "G" 会被当成元素）→
   formula 污染 4,342 → **0**

教训：**合成测试数据必须复现真实布局**。旧测试把标记紧跟在数据后、
只用 `P...X...`，与旧正则"恰好自洽"，把 bug 全部掩盖了。
`test_marker_anchored_at_column_71` / `test_continuation_tail_stripped_from_formula`
两条守卫就是为此加的。

### 0.2 类型 3 的晶胞体积落在 63~68 列，被 67 列截断（已修）

0.1 的"数据区截到 67 列"对多数子记录正确，但**类型 3 是例外**：
它的体积字段恰好写在 63~68 列。全库 35,020 行类型 3 逐行核对，
末位非空格字符 **100% 落在第 68 列**。

后果：体积被砍成 `"365."` → 解析失败 → 该字段全丢；更糟的是**建库哨兵
`vol_mismatch` 因此永远静默为 0**（哨兵本身被同一 bug 关掉了）。

修法：`_DATA_END_BY_CODE = {"3": 69}`，按子记录类型选数据区右边界。
修好后哨兵立刻报出 986 条偏差 —— 见第 4.1 节。

教训：**"某字段全空"与"该字段本就该空"必须区分**。加一条合成记录断言
（`test_type3_volume_only_from_decimal_field`）比看真实库统计更早暴露问题。

## 二、代码结构

| 文件 | 职责 |
|---|---|
| `src/polyxrd/services/pdf2_database.py` | 解析器 + 建库 + 查询服务 |
| `src/polyxrd/services/phase_identifier.py` → `identify_with_pdf2()` | 识别入口 |
| `src/polyxrd/config.py` → `get_pdf2_db_path()` / `set_pdf2_db_path()` | 路径配置 |
| `src/polyxrd/views/phase_view.py` | 「物相分析」数据源下拉 (含 PDF2 项) |
| `src/polyxrd/viewmodels/phase_vm.py` → `identify_phases(db_source="pdf2")` | GUI 接线 |

### 解析器

PDF-2 2004 是**定宽 80 字符**记录格式，每行末尾带记录 ID（如 `P010001XI`），
其中最后 1~2 个字符是**子记录标识**，用 `_RE_RECORD_ID` 正则切出。
`parse_pdf2_record()` 按标识分派：

| 标识 | 含义 | 本模块用途 |
|---|---|---|
| `1` | 主记录起始 | 记录边界 |
| `2` | 最强线 d 值 + 卡片质量标记 | — |
| `3` | **空间群 + 对称性数值** | `space_group(_num/_setting)` / `cell_vol` |
| `4` | 分子量等数值 | `molecular_weight` |
| `5` | 元素符号 / CAS 号 | `cas_number` |
| `6` | 名称（按 67~68 列分类） | `name`（P 类）/ `mineral`（M 类） |
| `7` | 化学式（原始写法） | `formula` |
| `8` | 化学式（规范化） | `formula_norm`（`formula` 为空时回退用它） |
| `9` | 文献引用 | `reference` |
| `A` | Pearson 符号 | `pearson`（晶系 + 点阵） |
| `C` | 约化↔常规胞变换矩阵 | **不入库**（语义无法自证，见 4.1） |
| `D` | **约化（原）晶胞** | `red_a~red_gamma` / `red_vol` |
| `E` | **常规晶胞** | `cell_a~cell_gamma` ← 对外暴露的晶胞 |
| `F` | 辐射类型 + 标记 | `radiation` |
| `G` | 质量标记 | `quality` |
| `I` | **d-I 峰列表** | `peaks_d` / `peaks_i` ← 识别的核心数据 |
| `B` | 注释 | `comment` |
| `K` | 维护信息 = 记录结束 | 终止解析 |

主要接口：`parse_pdf2_record()`、`iter_pdf2_records()`、
`PDF2DatabaseBuilder.build()`、`PDF2Database`。

### 类型 3 / E 的精确列位

实测 85,013 条记录逐条核对（`tests/test_pdf2_space_group.py` 有守卫）：

```
类型 3:  cols 0~7   空间群符号 (8 字符左对齐; 号=0 时这里是 Bravais 点阵字母)
         cols 8~10  标志位 ('E' / '*')
         cols 11~13 空间群号 (右对齐, 0 = 未定)
         col  14    设置字母 (A~F; 如 14A=P21/c, 14B=P21/a)
         cols 15~   体积 + 体积之前还有 Z 与两个密度 (均不入库, 见 4.1)
类型 E:  a b c α β γ [a/b, c/b]   ← 常规晶胞
类型 D:  a b c α β γ + 体积 + 1 个无关键序号
类型 3 尾段判据: 末字段含小数点才是体积 (Z 永远是纯整数 2/4/8/16/32)
```

**陷阱**：空间群号为 0 时，cols 0~7 放的是 Bravais 点阵字母 `P/A/B/C/I/F/R`，
不是空间群符号。照收就会得到 `space_group="F"` 这种既不是空间群、又与号 0
自相矛盾的取值 —— 全库 44,637 条无空间群的记录都靠这条判据分流
（`test_unknown_space_group_not_taken_as_bravais_letter`）。

**取值**：对外暴露的 `cell_a~cell_gamma` 取**类型 E（常规晶胞）**，不是类型 D。
方解石 E = 4.983 / 4.983 / 17.019 / 90 / 90 / 120（与文献一致），
D 是菱面体原胞 (4.983 / 4.983 / 6.361 / 66.94 / 66.94 / 60)。

### 查询服务 `PDF2Database`

接口刻意与 `CIFDatabase` 的 COD 侧保持同名同形，方便互换：

- `is_available()` / `phase_count()` / `stats()` / `coverage()`
- `get_phase(cod_id)` — 返回 `peaks_d_list` / `peaks_i_list`（与 `get_cod_phase` 同形），
  另带 PDF2 独有的 `name` / `mineral` / `space_group_num` / `pearson` / 约化胞
- `get_lattice(cod_id)` — 直接给 `LatticeParams`，供 Rietveld 取起始晶胞
- `search_phases(query, limit=)` — 按公式 / 卡片号 / 名称 / 矿物名搜
- `search_by_d_peaks(...)` — **直接复用** `CIFDatabase.search_cod_by_d_peaks`

`search_by_d_peaks` 是薄封装：构造一个 `CIFDatabase(enable_cod_local=False)`，
把它的 `_cod_conn` 指向 PDF2 连接后调用同一份 Hanawalt 实现。
这样 COD 与 PDF2 的**检索算法天然同口径**，不会各写一份慢慢漂移。

### 识别入口 `PhaseIdentifier.identify_with_pdf2()`

与 `identify_with_cod_inorganics()` 流程逐行对应：

```
default_peak_list(data)                    ← 与 COD 路径同一寻峰器
  → 峰 2θ → d 值
  → PDF2Database.search_by_d_peaks()       ← 与 COD 同一 Hanawalt 实现
  → elements_match_filter()                ← 与 COD 同一四态过滤
  → Phase(name="<矿物名> (PDF2 <id>)", space_group=…, lattice=…) 
  → _match_phase_fom()                     ← 与 COD 同一 FoM
  → cod_rank_score()                       ← 与 COD 同一排序口径
```

三处**必须共用同一实现**（已加回归守卫，见 `tests/test_pdf2_database.py`）：

1. 默认寻峰 → `default_peak_list()`，不用裸 `PeakFinder`
2. 排序 → 模块级 `cod_rank_score()`，不在方法内复制闭包
3. 库公式 → 元素集合 → `utils/formula_parser.elements_from_db_formula()` 单点实现

名称优先级 = **矿物名 > PDF2 主名称 > 化学式**（`Calcite` 比
`Calcium Carbonate Oxide` 更贴近检索习惯），全部带上 `(PDF2 010837)` 后缀。

## 三、GUI 对接

「物相分析」面板的**数据库源**下拉新增第 5 项 `PDF2-2004 库 (163,834)`：

- 物相数从库里**实时读取**，不写死
- 库文件不存在时该项**置灰**（避免选中后静默返回空结果），并在 tooltip 里
  给出实际覆盖率
- 选中后「传统 Search/Match」与「快速（无过滤）」都走 `identify_with_pdf2`
- 候选列表行尾带空间群标记（`· R-3c`），tooltip 显示化学式 / 空间群 /
  a,b,c,α,β,γ / V / 参考峰条数
- 命中相直接带 `lattice` → 精修向导可拿它当起始晶胞（此前只能从默认立方胞起步）

Profile Fitting 按钮**不受**该下拉影响（它走 `ProfileFittingService` 自己的
库路径），这一点在 tooltip 里已写明。

## 四、重建索引

原始 `.dat` 不在仓库里，换机器或换数据版本时需重建（587 MB → 约 55 s）：

```python
from polyxrd.services.pdf2_database import build_pdf2_database

stats = build_pdf2_database(
    r"E:/TEMP/XRD-PDF2-2004/pdf2 - 2004.dat",
    r"cod_data/PDF2_2004.sqlite",
    progress_cb=lambda n: print(n, end="\r"),
)
# {'total': 163835, 'ok': 163834, 'bad': 1, 'elapsed_s': 54.4,
#  'with_cell': 133935, 'with_sg': 119197, 'sg_unknown': 44637,
#  'with_name': 163833, 'vol_mismatch': 986}
```

`vol_mismatch` 是**解析布局哨兵**：用类型 E 六参数算出的体积与类型 3
报告体积相差 >2% 的条数。列位读错时它会从 ~986 跳到几万（0.2 节的 bug
就靠它定位）。正常值全部来自 ICDD 自身的数据口径差异，见 4.1。

路径也可通过配置覆盖（会持久化到 `~/.polyxrd/user_db_paths.json`）：

```python
from polyxrd.config import get_config
get_config().set_pdf2_db_path(r"D:/my/PDF2_2004.sqlite")
```

> `user_db_paths.json` 由 COD 与 PDF2 **共用**，读写一律按 key 增量合并。
> 曾出现过"设置 COD 路径把 PDF2 路径抹掉"的缺陷，已修并加回归守卫
> （`tests/test_config_db_paths.py`）。

## 五、已知限制

### 5.1 Z / 密度字段有意不入库

类型 3 尾段除体积外还有 `Z` 与两个密度（计算 / 实测），**故意不存**。

实测 45,557 条"约化胞 ≠ 常规胞"的卡片中：约 2,586 条只能用常规胞复现 Dx、
2,850 条只能用约化胞、3,770 条两者都不成立 —— 一致率约 80%。
根因是 `Z` 取自原始文献、`Dx` 由 ICDD 另算，**同一卡片内两者可以互相矛盾**。
典型例：刚玉 Al₂O₃ (卡片 11296) 报 `Z=2`，而 `Dx=3.97` 是按 `Z=6` 的六方胞
算出来的。

存一个自相矛盾的密度只会误导"按密度筛选"这类下游。同理，类型 C 的
约化↔常规胞变换矩阵也不入库 —— 方解石卡片给的是单位矩阵，与 D/E 两胞
明显不同构，语义无法自证。

### 5.2 类型 3 的报告体积有 0.736% 与 E 胞口径不同

986 / 133,925 条。偏差是**双峰**的，不是连续的：

| 区间 | 条数 | 占比 |
|---|---|---|
| <0.5%（精确吻合） | 132,939 | 99.264% |
| 0.5~2% | 0 | 0% |
| 2~10% | 0 | 0% |
| >10% | 986 | 0.736% |

中间带**一条都没有** —— 这是"数据口径差异"而非"解析错误"的指纹
（解析错会把偏差糊在中间）。两组成因：

- **321 条 hR 相**：报告的是菱面体原胞体积（E 胞的 1/3）。
  如 700280 R-3m，E 胞 V=780.0，报告 260.01 = V_D。
- **654 条 aP / tI / mP 相**：报告的是 E 胞的 2 倍（原始文献用了超胞）。
  如 21213 mP，E 胞 V=743.94，报告 1487.88 = 2×。

因此 `cell_vol` 一律用**入库六参数自算**（与 a,b,c,α,β,γ 自洽），
报告值只用于驱动建库哨兵。

### 5.3 空间群符号里可能含未定字符

ICDD 用 `*` 和 `,` 占位无法确定的下标，例如 `P*,-1`（实为 P-1，号 2）、
`P***`（实为 Pmmm，号 47）。本模块**原样保留**符号文本，不做猜测性还原 ——
需要精确对称性时请用 `space_group_num`（全库 119,197 条有值，
与 Pearson 符号的晶系一致率 **100%**）。

### 5.4 覆盖范围

PDF-2 2004 是**全集**（含有机物），而 COD 无机物库只含无机物。
元素过滤里若放开 C/H/N/O，PDF2 会返回大量有机相 —— 交叉验证时
建议显式设置 `element_filter`，或在对比时按 `formula` 剔除含 C/H 的候选。

老 Hanawalt 卡片（1930~50 年代）本就没有晶胞与空间群数据，缺失属正常：
晶胞 18.2% 缺失、空间群 27.2% 缺失主要来自这部分。

## 一、四态元素过滤

### 语义（已按用户定义实现）

记 **S** = 物相元素集合，**P/H/M/E** = 必有/含有/可能/没有 的元素集合：

| 类别 | 键名 | 判定式 | 含义 |
|---|---|---|---|
| 必有 | `must_have` | `P ⊆ S` | **全部必含 (AND)** |
| 含有 | `must` | `S ∩ H ≠ ∅` | 物相由 H 构成，至少含其中一个 |
| 可能 | `maybe` | 无强制条件 | 仅放宽允许池；**H 为空时代行 H 之职** |
| 没有 | `exclude` | `S ∩ E = ∅` | 含任一即淘汰 |

补充规则：

- **未勾选元素默认并入 E**（闭环，等价 `S ⊆ P∪H∪M`），**仅当 P∪H∪M 非空时启用**
- 三者全空 = 全库搜索；**只勾「没有」= 开放世界**（仅排除这些元素）
- **勾了必有时不再要求至少含一个含有**（纯金属 Mg 仍可作为候选）
- 重叠优先级：必有 > 含有 > 可能 > 没有

### 用户示例自检（全部通过）

| 输入 | 结果 |
|---|---|
| 含有{Mg,Ca,C,O} | MgO / CaO / CaCO₃ / MgCO₃ / CaMgCO₃ ✅；ZnO、CaSO₄ 被排除 ✅ |
| 必有{Mg} + 含有{Ca,C,O} | MgO / MgCO₃ / CaMgCO₃ ✅；纯 Mg 也可 ✅；CaCO₃ 排除 ✅ |
| 必有{Mg,Ca,C,O} | 仅 CaMgCO₃ ✅ |
| 含有{Al,O} + 可能{H} | Al₂O₃ / Al / Al(OH)₃ ✅ |
| 含有{Al,O}（不勾 H） | Al(OH)₃ 被默认排除 ✅ |

### 实现变更

- 判定收敛为**单一纯函数** `utils/formula_parser.elements_match_filter`，
  内置库 / COD 库 / Profile Fitting **三条路径统一调用**，删除了原先两套互不一致的写法
- 新增 `normalize_element_filter`（旧工程文件的 `must` 键自动映射到「含有」）
- 修复：`profile_fitting` 原先只在勾了「必须」或「不含」时才过滤 → 单独勾「可能」时完全失效
- 修复：COD 路径原先只勾「没有」时会**排除全部候选**（`allowed` 为空集导致子集判定失败）
- UI：周期表改为四态循环（无 → 必有 → 含有 → 可能 → 没有），新增
  **「轻元素设为含有 (O,C,H,N,S)」** 按钮，摘要栏显式提示「未勾选 N 种元素默认按没有排除」

## 二、匹配因子（FoM）重构

### 三点结构性修正

| # | 问题（旧口径） | 修正 |
|---|---|---|
| 1 | 每条参考峰各自就近吸附，**多条参考峰可命中同一条实验峰** → 峰多的密集物相被系统性高估 | **一一对应互斥匹配**（按 \|Δ2θ\| 升序贪心分配） |
| 2 | 归一化用 `Σ2θ` → 高角度相、多峰相**天然占优**，与匹配好坏无关 | 改用 `Σw` 归一，`w = 0.3 + 0.7·I/Imax`（强峰加权） |
| 3 | 无特异性约束；强度一致性用 `min/max` 比（对弱峰极不稳定） | 新增**未解释实验峰惩罚** + **匹配对强度余弦**（尺度无关） |

```
score = (bad + 0.30 · 未解释比) · (1 − 0.20 · 强度余弦)      bad ∈ [0, 2]
bad   = [Σ_命中 w·(|Δ2θ|/tol) + Σ_漏检 w] / Σ_all w
```

置信度分档收敛到 `models/fom.confidence_from_score`：`<0.15` 极好 / `<0.40` 良好 /
`<0.70` 一般 / 其余可能不匹配。`phase_identifier._match_phase_fom` 改为直接委托
`foam.compute_fom`，删除了重复实现。

### COD 排序口径变更

旧口径是字典序 `main_peak_match → top_precision → 加权召回 → 召回 → FOM`。
`main_peak_match` 是 **0/1 二值**——多相样品里只有主物相能拿 1，**其余真物相被整体压后**。
改为加权混合：

```
rank_score = 0.3 · Hanawalt复合 + 0.7 · (1 − clip(fom / 1.2, 0, 1))
Hanawalt复合 = 0.40·main_peak_match + 0.30·top_precision
             + 0.20·intensity_weighted_top_recall + 0.10·top_recall
```

### 基准结果（13 试样 / COD 无机物库 / 生产默认池 `prefilter_limit=100`）

预期物相在候选列表中的位次命中率（按化学式 + 名称比对）：

| 排序口径 | Top-1 | Top-5 | Top-10 |
|---|---|---|---|
| 旧（Hanawalt 字典序） | 12% (6/51) | 22% (11/51) | 24% (12/51) |
| 只用新 FoM | 16% (8/51) | 20% (10/51) | 29% (15/51) |
| **新（混合 0.3/0.7）** | **14% (7/51)** | **25% (13/51)** | **27% (14/51)** |

- **内置 118 物相库**：13 试样排序**无回归**（唯一变化：Boehmite 23→22）
- 若把预筛池放大到 200，混合口径可达 **Top-1 16% / Top-5 27% / Top-10 29%**
  （未改默认池，以控制单次识别耗时在 1.5–3 s）

## 三、检索召回优化（第二轮）

### 3.1 先否掉一个错误假设

第一轮报告把下一步定为「放宽 `search_cod_by_d_peaks` 的 d 容差 0.02→0.03、
提高 `max_ref_peaks`、主峰强度加权召回」。**实测证明这个方向收益极小。**

`tests/bench_cod_recall.py`（全量候选池，分母 = 可映射预期物相 45 条）:

| 配置 | 平均候选池 | 全量池命中 | @100 | @200 |
|---|---|---|---|---|
| base tol .02 / min_match 3 / max_ref 40 | 2549 | 38/45 | 26/45 | 29/45 |
| tol .02 + tol_rel 0.3% / m2 / r80 | 3760 | 39/45 | 26/45 | 29/45 |
| tol .03 / m2 / r80 | 3922 | 39/45 | 25/45 | 30/45 |

放宽容差与提高 `max_ref_peaks` 只多捞回 **1 条**真物相，@100 处甚至略降。
换预筛内部排序键（`bench_cod_sort.py`，10 种策略）最好也只有 **+1**。
**这两个都不是杠杆。**

### 3.2 真正的瓶颈定位

`tests/bench_cod_stages.py` 把链路拆成 5 段逐段统计存活率：

| 阶段 | Top-1 | Top-3 | Top-10 | Top-40 |
|---|---|---|---|---|
| A 全量候选池 | 4 | 6 | 9 | 17 |
| B 截断 @100 | 4 | 6 | 9 | 17 |
| C 纯 FoM 重排 | **7** | **9** | **15** | 20 |
| D 现混合排序 0.3h+0.7fom | 7 | 7 | **12** | 18 |
| E D → 去重 | 7 | 8 | 15 | 26 |

两个结论：

1. **预筛自身的排序键是弱判别器**（全量池 Top-10 只有 9/45），但它不致命 —— 只要
   多放候选进来，下游 FoM 就能把它们捞回来。
2. **`fom_good = 1 − clip(fom/1.2)` 会整体饱和**：多相样品里每个候选都解释不了大部分
   实测峰，FoM 普遍 > 1.2 → `fom_good` 全为 0 → `0.3h + 0.7fom_good` 退化成 `0.3h`，
   即把 FoM 信息完全丢弃。**越难的多相样品，退化越彻底。**

### 3.3 找到的最大杠杆：寻峰最小间距

诊断 3-1 试样（ZnO 占 **93.6%**）时发现：检测到的峰是 `36.24, 47.52, 56.58, …`，
**ZnO 最强的三条线 31.76°/34.40°/36.24° 里前两条整条消失**。

根因：`PeakFinder.find_peaks` 默认 `distance = 5.0`（**5 度**）最小峰间距，
而 XRD 峰半高宽只有 0.05~0.5°。scipy `find_peaks(distance=…)` 会直接删掉窗口内的
弱峰。后果：

| 试样 | 默认 8.8 峰 → | distance 修正后 |
|---|---|---|
| 3-1 (ZnO 93.6%) | 9 峰，缺 31.8/34.4 | 12 峰，补回 |
| 1-1 (LiFePO4) | 8 峰 | 25 峰 |
| 7-2 (7 相岩石) | **3 峰** | 14 峰 |

同时发现另一处：传统寻峰用「全局最大强度的百分比」做阈值，遇到「一条极强低角峰 +
其余弱峰」的谱会把其余峰全判为噪声。项目里已有的高精度检测器
`peak_detection`（局部噪声 σ 倍数 + 0.10° 间距）没有这个问题，但默认
`sigma_threshold = 5.0` 偏保守。

### 3.4 实施的改动

| # | 改动 | 位置 |
|---|---|---|
| 1 | 最小峰间距默认 `5.0° → 0.5°` | `services/peak_finder.py`、`config.py`、`viewmodels/{phase_vm,main_vm}.py`、`mcp_server/server.py`、`views/{data_view,main_window}.py` |
| 2 | 高精度寻峰 `sigma_threshold 5.0 → 3.0`（3σ 判据） | `services/peak_detection.py`、`viewmodels/{phase_vm,main_vm}.py` |
| 3 | 物相识别默认寻峰改用高精度检测器（带回退） | `services/phase_identifier.py` 新增 `default_peak_list()`，三处 `peaks=None` 分支统一调用 |
| 4 | COD 排序 `fom_good` 改 `exp(−fom/0.8)`，h 权重 `0.30 → 0.10` | `services/phase_identifier.py`（提为模块级 `cod_rank_score` 便于单测） |
| 5 | `search_cod_by_d_peaks` 新增 `tolerance_rel`（绝对下限 + 相对分量 `max(tol, tol_rel·d)`），并统一作用于全部 6 处判据 | `services/cif_database.py` |
| 6 | `identify_with_cod_inorganics` 暴露预筛旋钮 `prefilter_{tolerance,tolerance_rel,min_match,max_ref_peaks}` | `services/phase_identifier.py` |

`tests/bench_before_after.py` 同进程 2×2 因子对照（分母 = 可映射预期物相 45）：

| 寻峰 | 排序 | 平均峰数 | Top-1 | Top-3 | Top-5 | Top-10 | Top-20 | Top-40 | MRR |

  且 Top-5 略降。在 45 个样本点上**不具统计显著性**。保留它的理由是它修掉了一个
  明确的饱和缺陷（FoM 信息被整体丢弃），而不是因为它带来了可测量的提升。

## 四、仍未解决的问题（诚实汇报）

1. **单相 FoM 无法给混合物中的次要物相排序。** FoM 的「未解释实验峰」特异性惩罚
   是按单相样品设计的：5 相混合物里每个物相都解释不了 60~80% 的峰，FoM 因此对所有
   候选都偏高且趋同。这正是 3-1 试样里 Al₂O₃(5%) 排到 146 名、5-2b 里 CaCO₃ 排到
   895 名的原因。
   **正确的解法是组合选择**（项目已有 `_branch_and_bound_select` /
   `build_refinement_combination`），即从候选池里挑「联合覆盖实测峰最大」的物相子集，
   而不是逐个排序。目前该能力只在 Rietveld 前的组合阶段使用，未接入 COD 识别排序。
2. **基准度量本身有假阴性。** COD 把 ZnO 存为 `Li0.086 O0.957 Zn0.914` 这类
   掺杂/非化学计量式，`same_formula("ZnO", …)` 判定失败 → 3-1 记 0 分，但真物相
   其实排第 1。因此上表所有数字都是**下界**，真实性能更好。后续基准应改用
   「元素组成匹配 + 结构相似度」而非严格化学式。
3. **预筛仍会丢 7 条真物相**（45 条中），主要来自 `min_match=3` 的绝对门槛在
   峰数少的样品上过严（7-2 只有 3 个峰时要求 100% 全中）。
4. `PeakFinder` 传统寻峰的 `height`/`prominence` 仍是「相对全局 Imax」的阈值，
   对「一强多弱」谱不稳健。本次只修了 `distance`，阈值口径未动（高精度检测器
   已用局部噪声 σ，默认路径已切过去）。

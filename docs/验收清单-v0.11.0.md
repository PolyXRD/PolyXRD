# PolyXRD v0.11.0 人工验收清单

> 范围: 结构精修 —— **精修向导（引擎选 auto）** 与 **批量精修对话框**
> 方式: **源码模式验收**（不打包）。通过后再执行打包 (`build.bat`)。
> 数据: `E:\TEMP\test_xrd\txt\`（13 个真实试样）

---

## 0. 启动

```
E:\TEMP\PolyXRD\run_dev.bat
```

- 直接用仓库里的 `src/`，**永远是当前代码**，无需等 PyInstaller 构建。
- 等价的手工命令：
  ```
  set PYTHONPATH=E:\TEMP\PolyXRD\src
  E:\TEMP\PolyXRD\venv\Scripts\python.exe -m polyxrd.main
  ```
- 也保留了已安装的命令行入口：`venv\Scripts\polyxrd-gui.exe`（editable 安装指向同一份 `src/`）。

### 前置条件（每个用例都要）

1. **先加载数据**：把 `E:\TEMP\test_xrd\txt\` 里的某个 `.txt` 拖进主窗口
   （或 菜单「文件 → 打开」）。数据加载成功后「数据」页能看到图谱。
2. **先选出物相**：切到「物相分析」页跑一次识别，然后在候选列表里勾选物相。
   > 精修必须有选中物相。若一个都没勾，会回退用匹配分最高的前 3 个；
   > 若连匹配结果都没有，会提示「请先识别并选择物相」—— 这是**预期行为**，不是 bug。

### 建议试样

| 用途 | 试样 | 理由 |
|---|---|---|
| 单相、结构干净 | `1-1.txt` 等 | 验证 auto 走到 gsas2（真 Rietveld + wt%） |
| 四相混合 | `4-1.txt` | 验证多相 wt% 定量与批量表列宽 |
| 峰数少 | `7-2.txt` | 验证候选/物相不足时的降级提示 |

## 1. 用例 A：精修向导（引擎选 auto）

### 入口

- 工具栏「精修向导」按钮，**或** 菜单「结构精修 → 精修向导」。

### 步骤与预期

| # | 操作 | 预期 |
|---|---|---|
| A1 | 打开向导 | 对话框标题「精修向导」；**引擎下拉第一项且默认选中 `auto`** |
| A2 | 看引擎右侧状态标签 | 显示 **✓ 可用**（绿色）。鼠标悬停有说明，形如「自动择引擎: 全相有结构 CIF 且 GSAS-II 可用 → gsas2; 否则 builtin」 |
| A3 | 依次把引擎切到 `gsas2` / `powerxrd` / `maud` / `builtin` | 每次状态标签都随之刷新；已装的显示绿色 ✓，未装的显示橙色 ✗ |
| A4 | 选一个**橙色 ✗** 的引擎后点「确定」 | 弹警告框说明原因，并把下拉**改回 `builtin`**，且**不关闭对话框**（需要你再点一次「确定」）。这是防"静默回退"的设计 |
| A5 | 改回 `auto`，点「确定」 | 无警告，直接进入「结构精修」页并开始精修 |
| A6 | 观察状态栏 / 精修页日志 | 显示本次实际所用引擎；结果里能看到 wR / GOF |
| A7 | 展开结果详情 | 若 auto 最终走了 builtin，应能读到 **fallback 原因**（如「未找到 GSAS-II 安装」「存在无结构 CIF 的物相」） |

### 关键校验点（本轮刚修的静默失效）

> **A3/A8 是重点**：`engine` 必须真的传到精修引擎。
> 历史缺陷：向导的引擎下拉**选了等于没选** —— `_on_refine_wizard` 把
> `params["engine"]` 丢掉了，恒用默认 `builtin`。现已修复并加了回归测试。
>
> 复核方法：选 `gsas2` 跑一次，与选 `builtin` 跑一次，
> **wR / 耗时应有明显差异**；若两者完全一致，说明又漏传了。

| # | 操作 | 预期 |
|---|---|---|
| A8 | 同一样品分别用 `builtin` 和 `gsas2` 各精修一次 | 两者结果**不同**（引擎确实换了） |
| A9 | 把「2θ 起始/结束」改成只覆盖前一半峰，再点确定 | 精修实际只在窗口内做；若窗口内数据点 < 3，应弹出**明确提示**「2θ 窗口 [...] 内仅 N 个数据点，不足以精修 (需 ≥ 3)」而不是崩栈 |
| A10 | 把「波长」从 1.5406 改成 1.7889（Co Kα），再点确定 | 波长真的生效（d 值/峰位随之变化），不是装饰控件 |

## 2. 用例 B：批量精修对话框

### 入口

- 菜单「结构精修 → **批量精修**」。
- **前提**：已在「物相分析」页勾选至少一个物相。未勾选时会提示并自动跳到物相页 —— 预期行为。

### 步骤与预期

| # | 操作 | 预期 |
|---|---|---|
| B1 | 打开对话框 | 标题「批量精修」，含文件夹选择、引擎下拉、循环数、开始/取消、结果表 |
| B2 | 看引擎下拉 | 含 **`auto` / `gsas2` / `maud` / `builtin` / `powerxrd`**，默认 `auto` |
| B3 | 「浏览」选 `E:\TEMP\test_xrd\txt\` | 路径填入，可点「扫描」 |
| B4 | 点「扫描」 | 提示找到 N 个数据文件（N 应为 13 左右，取决于目录内文件类型） |
| B5 | 点「开始」 | 表格逐行增加；进度推进；**UI 不卡死**（后台线程） |
| B6 | 观察进度与状态 | 「完成 x/y」连续递增；单文件失败**不中断**整批，该行标为失败并带原因 |
| B7 | 中途点「取消」 | 停止后续文件，已完成的保留在表里；状态正确收尾（不是"卡在运行中"） |
| B8 | 全部跑完 | 弹「完成」汇总（成功数/总数） |
| B9 | 点「导出 CSV」 | 文件保存成功，状态栏提示路径；用 Excel 打开**中文不乱码**（utf-8-sig） |
| B10 | 关掉对话框再重开 | 无残留状态；上一次的结果不串味 |
| B11 | 选一个不存在的/空的文件夹后点「开始」 | 明确的提示（未选文件夹 / 没有文件），不崩 |

### CSV 应含列

`文件 / 引擎 / (各物相 wt%) / 备注`

- 「引擎」列是**实际**使用的引擎（auto 会显示它最终落到哪个）。
- 「备注」列在发生回退时写入原因。

## 3. 引擎可用性对照（本机实测）

> 下表为 2026-09-14 在开发机上实跑 `RietveldRefiner().get_engine_status()` 的结果。

| 引擎 | 本机实测 | 说明 |
|---|---|---|
| `builtin` | ✓ 可用 | 内置 Rietveld（median 背景 + Caglioti + 多起点）|
| `auto` | ✓ 可用（**resolves_to = gsas2**）| 策略项：全相有结构 CIF 且 GSAS-II 可用 → gsas2，否则 builtin |
| `gsas2` | ✓ 可用 | 子进程桥 `scripts/gsas2_bridge.py` |
| `powerxrd` | ✓ 可用 | v4，**仅单相立方晶系**，其余自动回退内置 |
| `maud` | ✓ 可用 | MaudText 子进程；**每个 phase 必须带 `cif_path` 或 `cod_id`**，否则弹提示回退 |

四个界面（精修向导 / 精修视图 / 多页向导 / 批量精修）的引擎下拉现已统一为
`auto, gsas2, powerxrd, maud, builtin`，避免"这处能选、那处选不到"。

> `maud` 特别说明：若物相是通过 COD 检索得到且已关联 `cod_id`，可直接跑；
> 若物相没有结构来源，向导会在点「确定」时提示并回退 `builtin`。
> 这是已知约束（不是 bug），见 `docs/MAUD批处理侦察报告.md`。

| **B**（推荐） | 双击 `run_dev.bat` | 保留控制台，崩溃时能看到完整回溯并停住 |
| **C** | 终端里手工起 | 需要自己设 PYTHONPATH |

方式 C 的手工命令：

```
set PYTHONPATH=E:\TEMP\PolyXRD\src
E:\TEMP\PolyXRD\venv\Scripts\python.exe -m polyxrd.main
```

### ⚠️ 若双击 `run_dev.bat` 闪退（已修复，备忘）

首版 `run_dev.bat` 双击会**一闪就关**。根因**不是 Python**（程序本身稳定运行），
而是 bat 文件的 cmd.exe 语法问题：

- `echo ... (见 README / handover 文档)` 里的**裸 `)` 提前闭合了
  `if not exist (...)` 代码块** —— cmd 的经典陷阱。后续的 `pause` / `exit /b 1`
  被当成顶层语句，解析失败 → cmd 放弃执行整个 bat → 窗口一闪即关，
  **`pause` 根本没机会运行**，所以连报错都看不到。
- 附带隐患：文件是 LF 换行（cmd 按字节偏移定位标签，需 CRLF）；
  `endlocal` 之后才展开 `%RC%`（变量已被 setlocal 丢弃，退出码恒为 0）。

修法是**把文件削到最不可出错的形式**（12 行有效命令，只用最老牌的写法）：

- 纯 ASCII + CRLF；
- 全部 `if` 都是单行，且用 `if errorlevel 1 pause` 这个无变量、无引号比较、
  无括号的经典惯用法（连"取 ERRORLEVEL 存变量"这一步都省掉，从根上消除
  变量展开类问题）；
- 不用 `setlocal` / `endlocal` / `goto` / 标签。

`tests/test_run_dev_bat.py`（17 项）把这些约束固化成断言，防止再犯。
该护栏已用**还原出的首版缺陷文件**验证过：能精确报出 5 处问题
（CRLF、非 ASCII、if 行括号、echo 文本括号、setlocal），修复版 17/17 通过。

> ⚠️ **诚实说明**：本机的安全策略禁止我从脚本里调用 `cmd.exe`，
> 因此**我无法在这里替你实跑一遍 `run_dev.bat`**。已验证的是：
> ① bat 文件本身通过全部 17 项结构断言；② 它要执行的那条命令
> （`venv\Scripts\python.exe -m polyxrd.main`，带 PYTHONPATH=src）
> 已实测稳定运行 12 秒以上；③ `venv\Scripts\polyxrd-gui.exe` 同样实测可用。
> 若双击仍有问题，请用**方式 A** 或方式 C 先跑起来，并把终端/日志内容发我。

> 顺带修了 `main.py` 的一个潜在崩溃：若启动图路径存在但图片读不出来，
> `splash` 变量从未绑定，会在 `app.exec()` 之前 `UnboundLocalError` →
> 表现为"启动即闪退、连主窗口都不出现"。已改为先初始化 `splash = None`
> 并判空引用；`tests/test_main_entry.py`（7 项）用该场景做了回归，
> 并已确认能在旧代码上报出 `UnboundLocalError`。

### 前置条件（每个用例都要）

1. **先加载数据**：把 `E:\TEMP\test_xrd\txt\` 里的某个 `.txt` 拖进主窗口

## 1. 两条精修向导路径

应用里同时提供**两套向导**，功能互补，用户按需挑 —— 两处入口：

| 入口 | 位置 |
|---|---|
| 菜单 | 「结构精修 → **精修向导（快速）**」/「结构精修 → **精修向导（分步）**」 |
| 工具栏 | 「精修向导」按钮：**点主体 = 快速版**；**点右侧小箭头**展开两条路径 |

| | 快速版 | 分步版 |
|---|---|---|
| 形态 | 单页参数对话框 | 5 步向导（数据 → 物相 → 参数 → 预览 → 执行） |
| 收的参数 | 引擎 / 策略 / 循环 / 波长 / 2θ 窗口 | 同上 + 背景方法 / 峰形 + 模板管理 |
| 额外能力 | — | **CIF 导入、COD 在线检索、配置预览** |
| 谁跑精修 | 主 ViewModel | 向导**自带 refiner 独立跑**，完成后结果回灌到精修页 |
| 适合 | 已经选好物相、只想快点出结果 | 想从头走一遍、或要临时加物相 / 试模板 |

> 两条路径最终结果都落到同一个「结构精修」页，报告/导出无需区分来源。

## 2. 用例 A：精修向导（快速版，引擎选 auto）

### 入口

- 工具栏「精修向导」按钮（点主体），**或** 菜单「结构精修 → 精修向导（快速）」。

### 步骤与预期

| #  | 操作                                                | 预期                                                                            |
| -- | ------------------------------------------------- | ----------------------------------------------------------------------------- |
| A1 | 打开向导                                              | 对话框标题「精修向导」；**引擎下拉第一项且默认选中 `auto`**                                           |
| A2 | 看引擎右侧状态标签                                         | 显示 **✓ 可用**（绿色）。鼠标悬停有说明，形如「自动择引擎: 全相有结构 CIF 且 GSAS-II 可用 → gsas2; 否则 builtin」 |
| A3 | 依次把引擎切到 `gsas2` / `powerxrd` / `maud` / `builtin` | 每次状态标签都随之刷新；已装的显示绿色 ✓，未装的显示橙色 ✗                                               |
| A4 | 选一个**橙色 ✗** 的引擎后点「确定」                             | 弹警告框说明原因，并把下拉**改回 `builtin`**，且**不关闭对话框**（需要你再点一次「确定」）。这是防"静默回退"的设计           |
| A5 | 改回 `auto`，点「确定」                                   | 无警告，直接进入「结构精修」页并开始精修                                                          |
| A6 | 观察状态栏 / 精修页日志                                     | 显示本次实际所用引擎；结果里能看到 wR / GOF                                                    |
| A7 | 展开结果详情                                            | 若 auto 最终走了 builtin，应能读到 **fallback 原因**（如「未找到 GSAS-II 安装」「存在无结构 CIF 的物相」）    |

### 关键校验点（本轮刚修的静默失效）

> **A3/A8 是重点**：`engine` 必须真的传到精修引擎。  
> 历史缺陷：向导的引擎下拉**选了等于没选** —— `_on_refine_wizard` 把  
> `params["engine"]` 丢掉了，恒用默认 `builtin`。现已修复并加了回归测试。
>
> 复核方法：选 `gsas2` 跑一次，与选 `builtin` 跑一次，  
> **wR / 耗时应有明显差异**；若两者完全一致，说明又漏传了。

| #   | 操作                                  | 预期                                                                           |
| --- | ----------------------------------- | ---------------------------------------------------------------------------- |
| A8  | 同一样品分别用 `builtin` 和 `gsas2` 各精修一次   | 两者结果**不同**（引擎确实换了）                                                           |
| A9  | 把「2θ 起始/结束」改成只覆盖前一半峰，再点确定           | 精修实际只在窗口内做；若窗口内数据点 < 3，应弹出**明确提示**「2θ 窗口 [...] 内仅 N 个数据点，不足以精修 (需 ≥ 3)」而不是崩栈 |
| A10 | 把「波长」从 1.5406 改成 1.7889（Co Kα），再点确定 | 波长真的生效（d 值/峰位随之变化），不是装饰控件                                                    |

## 3. 用例 B：精修向导（分步版）

这版向导此前一直没接进主窗口（属于"写好了但没人能打开"的状态），本轮已挂上。

### 入口

- 菜单「结构精修 → **精修向导（分步）**」，**或** 工具栏「精修向导」按钮右侧小箭头 → 「精修向导（分步）」。

### 步骤与预期

| #   | 操作                                        | 预期                                                                       |
| --- | ----------------------------------------- | ------------------------------------------------------------------------ |
| B1  | 打开分步向导                                    | 弹出大窗口，标题「精修向导（分步）」；顶部有 `📋 步骤 1 / 5` 提示                                |
| B2  | 第 1 步「选择数据」                              | **已自动带入当前加载的数据**（不用重选）；能改起始/结束 2θ；起始 ≥ 结束 时应被拦住并提示                       |
| B3  | 点「下一步」进第 2 步「选择物相」                        | **已自动带入主窗口当前选中的物相**；下方表格列出它们                                            |
| B4  | 在第 2 步试「CIF 数据库」页签                        | 能列出本地 CIF 库物相；选中后点「添加选中物相」⇒ 进入已选表                                        |
| B5  | 试「COD 在线搜索」页签                             | 输入化学式（如 `ZnO`）点「搜索」⇒ 有结果则可「添加选中」；无网络时应提示失败而不是卡死                            |
| B6  | 第 3 步「参数设置」                               | 模板下拉第一项是 **「自动选择（推荐）」**，且**引擎应显示 `auto`**；切别的模板，引擎/策略/背景/峰形/循环数应跟着变     |
| B7  | 手动把引擎改成 `gsas2`                            | 下拉能选到（含 `auto`/`gsas2`/`maud`/`builtin`/`powerxrd` 五项）                     |
| B8  | 第 4 步「预览确认」                               | 汇总显示数据点数/2θ 范围/波长、物相列表、精修参数 —— 与前面几步的设置一致                                |
| B9  | 第 5 步「执行精修」→ 点「开始精修」                      | 进度条推进；日志区打印引擎/策略（如 `引擎: auto`）；**UI 不卡死**                              |
| B10 | 精修结束                                      | 执行页显示 wR / GOF / 质量评级 / 循环次数 / 耗时；日志逐相打印 wt%                              |
| B11 | **关闭分步向导后看主窗口**                           | ① 自动切到「结构精修」页；② 该页显示的结果**与向导里的一致**；③ 状态栏有「分步向导精修完成…」提示 ← **本轮合并的关键点** |
| B12 | 在第 5 步之前点「取消」                             | 向导关闭，主窗口**不产生**新结果（旧结果保留），不崩                                             |
| B13 | 没加载数据 / 没选物相时从菜单打开分步向导                    | 明确提示「请先加载数据」/「请先…选择物相」，**不弹一个空向导**                                       |
| B14 | 在向导里点「保存为模板」，输入名字                         | 提示保存成功；重新打开向导时该模板出现在下拉里；**别动主窗口已选物相**（向导内部用副本）                           |

### 与快速版的关键差异（也是本轮改动点）

> **B11 是重点**。分步向导**自带 refiner 独立执行**，结果不经过主 ViewModel。
> 因此本轮专门加了回灌通道（`adopt_refinement_result`）—— 否则用户会在向导里
> 看到漂亮的 wR，回到主窗口却发现「结构精修」页还是空的。这正是"合并两套向导"
> 最容易漏掉的一环，已用测试守住。

## 4. 用例 C：批量精修对话框

### 入口

- 菜单「结构精修 → **批量精修**」。
- **前提**：已在「物相分析」页勾选至少一个物相。未勾选时会提示并自动跳到物相页 —— 预期行为。

### 步骤与预期

| #   | 操作                            | 预期                                                                 |
| --- | ----------------------------- | ------------------------------------------------------------------ |
| C1  | 打开对话框                         | 标题「批量精修」，含文件夹选择、引擎下拉、循环数、开始/取消、结果表                                 |
| C2  | 看引擎下拉                         | 含 **`auto` / `gsas2` / `maud` / `builtin` / `powerxrd`**，默认 `auto` |
| C3  | 「浏览」选 `E:\TEMP\test_xrd\txt\` | 路径填入，可点「扫描」                                                        |
| C4  | 点「扫描」                         | 提示找到 N 个数据文件（N 应为 13 左右，取决于目录内文件类型）                                |
| C5  | 点「开始」                         | 表格逐行增加；进度推进；**UI 不卡死**（后台线程）                                       |
| C6  | 观察进度与状态                       | 「完成 x/y」连续递增；单文件失败**不中断**整批，该行标为失败并带原因                             |
| C7  | 中途点「取消」                       | 停止后续文件，已完成的保留在表里；状态正确收尾（不是"卡在运行中"）                                 |
| C8  | 全部跑完                          | 弹「完成」汇总（成功数/总数）                                                    |
| C9  | 点「导出 CSV」                     | 文件保存成功，状态栏提示路径；用 Excel 打开**中文不乱码**（utf-8-sig）                      |
| C10 | 关掉对话框再重开                      | 无残留状态；上一次的结果不串味                                                    |
| C11 | 选一个不存在的/空的文件夹后点「开始」           | 明确的提示（未选文件夹 / 没有文件），不崩                                             |

### CSV 应含列

`文件 / 引擎 / (各物相 wt%) / 备注`

- 「引擎」列是**实际**使用的引擎（auto 会显示它最终落到哪个）。
- 「备注」列在发生回退时写入原因。

## 5. 引擎可用性对照（本机实测）

> 下表为 2026-09-14 在开发机上实跑 `RietveldRefiner().get_engine_status()` 的结果。

| 引擎         | 本机实测                          | 说明                                                          |
| ---------- | ----------------------------- | ----------------------------------------------------------- |
| `builtin`  | ✓ 可用                          | 内置 Rietveld（median 背景 + Caglioti + 多起点）                     |
| `auto`     | ✓ 可用（**resolves_to = gsas2**） | 策略项：全相有结构 CIF 且 GSAS-II 可用 → gsas2，否则 builtin               |
| `gsas2`    | ✓ 可用                          | 子进程桥 `scripts/gsas2_bridge.py`                              |
| `powerxrd` | ✓ 可用                          | v4，**仅单相立方晶系**，其余自动回退内置                                     |
| `maud`     | ✓ 可用                          | MaudText 子进程；**每个 phase 必须带 `cif_path` 或 `cod_id`**，否则弹提示回退 |

四个界面（精修向导 / 精修视图 / 多页向导 / 批量精修）的引擎下拉现已统一为  
`auto, gsas2, powerxrd, maud, builtin`，避免"这处能选、那处选不到"。

> `maud` 特别说明：若物相是通过 COD 检索得到且已关联 `cod_id`，可直接跑；  
> 若物相没有结构来源，向导会在点「确定」时提示并回退 `builtin`。  
> 这是已知约束（不是 bug），见 `docs/MAUD批处理侦察报告.md`。

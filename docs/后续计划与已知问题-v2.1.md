## 一、已知问题（按优先级，均附证据）

### P1 · 复杂多相精修耗时过长（7-1 七相 25 分钟未跑完）

- **现象**：W29 基准里 7-1（七相、约 3000 条参考峰）在 25 分钟时被人工终止，其余试样 10–160 s。
- **原因**：**不是不收敛**，而是"抛光"阶段固定做 **675 次谱合成评估**，每次都要在 ~7251 个数据点上
  叠加 ~3000 条峰 → 单次评估代价随峰数近似线性甚至更差。
- **建议**：抛光评估预算按峰数**自适应**（如 `budget ≈ clamp(675 × 3000/N_peaks, 40, 675)`），
  或峰数超阈值时直接跳过抛光（此时改用多起点 + 热启动保证质量）。
- **验收**：7-1 在 15 分钟内跑完，且 wR 不比"跳过快检的精细模式"更差。

### P1 · 本轮新增的服务层提示未国际化（违反项目自身约定）

- **现象**：Kα2 提示、拟合诊断建议、指标口径提示都是**中文自然语言字符串**，
  由 `services/rietveld_refiner.py` 直接生成并进入 `result.warnings` / `metric_note`，
  界面（结果区提示条、精修向导日志）原样显示 → **英/日界面出现中文**。
- **原因**：项目约定是"**服务层不依赖 i18n**，日志只用技术符号+数值，要本地化的措辞由界面自己包"
  （见 `rietveld_refiner.py` 模块文档与 CHANGELOG v1.1.1 的服务层符号化改造）。
  本轮为了实现"可读诊断"直接写了中文，破了这条约定。
- **建议**：服务层改为返回**结构化诊断**（`code` + `params`，如
  `{"code": "diag.high_angle", "params": {"high": 12.3, "low": 4.1}}`），
  由 UI 用 `tr()` 渲染；三种语言各补一组键。
- **验收**：en/ja 界面下诊断与提示全为对应语言；离屏残留扫描（v1.1.1 那套）保持 0。

### P2 · 结构回填命中率与"口径可见性"

- **现象**：1-2（NCM 811）从本地 COD 回填结构失败（0/1 相）→ 定量口径退回 `relative`；
  该样本同时耗时 157 s（受 P1 影响）。
- **影响**：这类试样拿不到严格质量分数（`W∝S·ZMV`）。
- **建议**：增强回填检索（化学式归一化、空间群宽松匹配、多候选打分），
  并把"为什么没回填上"暴露到界面（当前只有 `weight_basis` 字段，用户不可见）。
- **验收**：8 试样中回填成功率 ≥ 7/8；失败时界面明确提示口径已降级。

### P2 · 真实 Bragg R（`Rb`）未实现

- **现状**：历史 `Rb` 字段的公式其实是**轮廓 R**，被误标为 Bragg R。
  v2.0.0 已把轮廓 R 正名为 `Rp`，`Rb` 置为**废弃槽位（恒 0）**，不再冒充。
- **待做**：真 Bragg R = `Σ_hkl |I_obs,hkl − I_calc,hkl| / Σ I_obs,hkl`，
  需要按反射提取观测积分强度（`refine_le_bail` 里已有 Le Bail 式强度提取循环可复用）
  并与 `|F|²·m·LP` 对账。
- **验收**：合成双相数据上 Bragg R 与解析值一致（<5% 相对）。

### P2 · Kα2 只有"检测 + 提示"，没有建模

- **现状**：`detect_ka2` 用形状无关的对称性判据检出（真实数据 2-1/1-1/3-1 命中），
  只在结果区给出"建议剥离或启用建模"的提示。
- **待做**：模型加 Kα2 分量（λ2、强度比 0.5、解析 Δ2θ），opt-in 默认关。
- **验收**：合成 Kα2 数据回收强度比 0.5±0.05；2-1 的高角残差明显下降。

## 三、外挂数据库兼容性说明（v1.1.1 → v2.0.0）

**结论：两个 COD 索引包（`COD-inorg-index` / `COD-full-index`）可继续使用，无需重新下载。**

- v2.0.0 对数据库只做了一处**向后兼容**改动：给 `cod_atomic_sites` 增加**可空列 `u_iso`**，
  通过**幂等的 `ALTER TABLE ... ADD COLUMN`** 在首次连接时自动补齐；
  若尚未补列，读取路径会自动回退到不含该列的查询并填入默认值 `U_iso = 0.005 Å²`
  （同时标记 `u_iso_default`），因此**不会因为旧库而报错或丢数据**。
- **实测证据**（发布前复核）：
  - `cod_data/cod_index.sqlite`（452 MB / 5,135,262 位点）在本轮基准运行中被**自动迁移**，
    现 `u_iso = True`；
  - `COD_inorganics_index.sqlite` / `COD_inorganics.sqlite`（各 311,126 位点）仍为 `u_iso = False`，
    但读写正常（走回退路径）。
- **内置参考库**（`xrd_reference_database.json`，库 0.5.1 → 0.5.2：hkl 重索引 + 峰表与晶胞自洽）
  **随安装包分发**，用户无需任何操作即获得修复。
- 因此本次 Release **不附带数据库包**；已有 v1.1.1 及更早的索引包可直接沿用。
